# Governance

The project currently uses a maintainer-led model. The primary maintainer is responsible for scope, releases, security response, and final merge decisions.

Decisions should favor reproducibility, narrow interfaces, synthetic tests, backward-compatible schemas, and honest limits. Material changes to evidence identity, validation rules, comparison thresholds, or security boundaries require a written design note and review before merge.

If additional maintainers join, responsibilities and decision rights will be recorded here. Maintainer status will reflect sustained review, issue triage, releases, and community support—not automated activity or nominal titles.
